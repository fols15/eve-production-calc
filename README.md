# EVE Production Calculator (private, local)

Локальный калькулятор себестоимости и прибыли производства для EVE Online.
Цены берутся напрямую из ESI (реальные рыночные ордера). Материалы всегда
оцениваются по станции **Jita IV - Moon 4 - Caldari Navy Assembly Plant** —
это цена закупки, а не место постройки. Продажа готового предмета (выручка)
может считаться в любой системе — см. «Где продавать» ниже.

Приватность обеспечивается тем, что сервер слушает только `127.0.0.1` —
доступ есть только с этого компьютера.

## Запуск

```
npm start
```

Откроется на http://127.0.0.1:3099/. Оставьте окно/процесс запущенным,
пока пользуетесь калькулятором. Остановить — закрыть терминал или
`Get-Process node | Stop-Process`.

## Как пользоваться

1. Найдите предмет через поиск (по названию).
2. Укажите количество единиц и ME чертежей (0–10, применяется одинаково
   ко всем чертежам в цепочке).
3. Нажмите «Рассчитать» — построится полное дерево производства до сырья.
4. У каждого производимого узла есть чекбокс «строить»: снимите его,
   чтобы вместо постройки купить этот компонент по рынку (Quick Buy) —
   сервер пересчитает всё дерево заново (короткий запрос, доли секунды —
   сервер локальный) и таблица затрат обновится.
5. Выберите систему производства (по умолчанию Jita) и налог комплекса,
   % — от этого зависит job cost (стоимость установки джоба): считается
   как EIV материалов × (индекс стоимости системы + налог комплекса),
   отдельно для каждого узла дерева, который вы строите.
6. Внизу — таблица затрат (материалы по Quick Buy + job cost), выручка
   (Quick Sell = мгновенная продажа в ордер на покупку; Sell = по текущей
   минимальной цене продажи/instant buy) и прибыль. Кнопка «Оптимизировать
   build/buy» учитывает job cost при выборе, что дешевле — построить узел
   или купить его готовым.
   - **Где продавать**: отдельный от «Система производства» выбор системы —
     влияет только на выручку готового предмета (материалы всё равно всегда
     по ценам Jita 4-4). Полезно, если строите в одном месте, а продаёте в
     другом (например, домашний регион). По умолчанию — тоже Jita.
7. Кнопка «🔍 Найти лучшую систему» сканирует все системы в пределах
   10 прыжков от Jita, где есть NPC-станция с услугой Manufacturing (не
   просто «есть какая-то станция» — большинство NPC-станций это торговые
   хабы/склады/рефайнери и строить там нельзя; фильтр проверяет реальный
   набор услуг станции по SDE), пересчитывает job cost + оптимальный
   build/buy для каждой и выдаёт топ-10 по итоговой стоимости постройки
   (с прыжками, индексом системы и станциями). Кнопка «Выбрать» в строке
   сразу пересчитывает производство в этой системе. Свои структуры (см.
   ниже) показываются в этом же списке (🏗️), с их собственным налогом,
   независимо от места в рейтинге.
   - **Игнорировать системы**: над таблицей можно добавить одну или
     несколько систем, которые нужно обходить (небезопасный маршрут,
     заблокированный гейт и т.п.) — и подбор прыжков, и сам подбор систем
     их не пересекают, поэтому расстояния и топ-10 пересчитываются так,
     будто этих систем нет на карте.
   - Кнопка **«Путь»** в строке разворачивает фактический маршрут по
     стар-гейтам от Jita до этой системы (с учётом того же списка
     игнорируемых систем).

## Как считается себестоимость (важно для доверия к цифрам)

Один и тот же материал/компонент часто нужен во МНОГИХ разных местах
дерева производства сразу, причём в очень разном количестве (например,
Vagabond требует «Fernite Carbide» в 7 разных местах — от 284 до 200 495
единиц). Реакции и производство идут партиями (округление вверх до целых
ранов), поэтому себестоимость единицы при заказе 284 штук совсем не такая,
как при заказе 200 495 (в одном реальном тесте — 1 403 ISK/ед. против
30 ISK/ед., разница в 46 раз для одного и того же материала).

Поэтому расчёт идёт в два прохода, как планирует production реальный
индустриалист в EVE:
1. Сначала по всему дереву суммируется ОБЩАЯ потребность в каждом
   компоненте (сколько единиц нужно всего, а не в каждом отдельном месте).
2. Затем для каждого компонента ОДИН раз решается — строить или купить —
   на основе этой общей потребности, и считается стоимость одной
   объединённой партии.

Все числа (себестоимость, job cost, решение build/buy) считает сервер —
браузер их не пересчитывает, только показывает. Это осознанный выбор:
более ранняя версия пыталась пересчитывать всё на клиенте при каждом
клике по чекбоксу, и из-за независимого пересчёта одного и того же
компонента в разных ветках дерева получала завышенные, противоречивые
итоги.

## Поиск лучшего предмета по прибыли — «💰 Поиск по прибыли»

Кнопка в шапке открывает панель: указываете диапазон прибыли (ISK) и ME —
сайт перебирает **все** ~5000 производимых предметов игры (по 1 рану
чертежа каждый), для каждого считает build/buy-оптимальную себестоимость
(Jita, 0% налог комплекса) и выручку (Sell по текущей минимальной цене
продажи), и показывает те, чья прибыль попадает в диапазон — отсортированные
по убыванию. Кнопка «Открыть» в строке сразу переносит на карточку этого
предмета с уже готовым расчётом.

Это тяжёлая операция (тысячи запросов цен к ESI) — первый запуск обычно
занимает 30–90 секунд, повторные запросы (даже с другим диапазоном)
почти мгновенны, пока не истёк 5-минутный кэш цен.

## LP-магазины (Guristas / State Protectorate) — «🎖️ LP-магазины»

Кнопка в шапке открывает панель со всеми офферами LP-стора Guristas и
State Protectorate (ESI, публичные данные — вход не нужен, LP-стор не
привязан к персонажу). Для каждого оффера считается:

- **Затраты** = ISK-цена + стоимость доп. предметов для сдачи (если есть,
  по цене Quick Buy);
- **Ценность** = рыночная стоимость награды;
- **Прибыль** = ценность − затраты;
- **ISK/LP** = прибыль ÷ LP-цена — метрика для сравнения офферов между
  собой (у самого LP нет фиксированной цены в ISK, это результат
  миссий/фарма, а не покупки).

Награды-**чертежи** (Guristas, например, часто продаёт именно чертежи
имплантов «Hydra», а не сами импланты) оцениваются через тот же движок
постройки: обычных рыночных ордеров на чертежи не существует, поэтому
ценность/затраты — это стоимость и выручка ОДНОГО рана постройки на
указанном ME. ESI не сообщает число ранов у чертежа с LP-стора, так что
это консервативная оценка (не полная ценность копии на много ранов).
Кнопка «Открыть» у такого оффера переносит на карточку самого предмета
(не чертежа), с уже готовым расчётом.

## Свои структуры (Raitaru/Azbel/Sotiyo и т.д.) — «🏗️ Мои структуры»

ESI не даёт способа спросить «покажи все Raitaru рядом с Jita» — только по
точному ID, по названию, которое ввёл сам игрок, или список структур
**своей же корпорации** (и то только если вы в ней директор). Поэтому:

- **Вручную**: в панели «Мои структуры» добавьте название, систему, тип
  (по желанию) и налог комплекса — она тут же появится в «Найти лучшую
  систему» и посчитается с правильным индексом её системы.
- **Через EVE SSO** (автоматически подтягивает структуры вашей
  корпорации, если вы директор): заведите приложение на
  [developers.eveonline.com/applications](https://developers.eveonline.com/applications) —
  тип «Authentication & API Access», Callback URL
  `http://localhost:3099/auth/callback`, scopes
  `esi-corporations.read_structures.v1`, `esi-universe.read_structures.v1`,
  `esi-skills.read_skills.v1`, `esi-characters.read_standings.v1`.
  Вставьте Client ID/Secret в панели «Мои структуры» → «Войти через EVE SSO»
  → «Синхронизировать структуры корпорации». Токены хранятся только
  локально в `data/user/auth.json`, никуда не отправляются кроме
  `login.eveonline.com`/`esi.evetech.net`.
- Налог комплекса ESI не отдаёт ни для своих, ни для чужих структур —
  его нужно указать/поправить вручную (поле «Налог, %» редактируется
  прямо в списке).

## Налоги персонажа (Sales Tax / Broker's Fee)

В той же панели «🏗️ Мои структуры» — блок «Налоги персонажа». Кнопка
«Подтянуть из аккаунта» (после входа через EVE SSO) читает скиллы
Accounting и Broker Relations и репутацию к Caldari Navy (владельцу Jita 4-4)
и считает по формулам CCP (патч 22.02, март 2025):

```
Sales Tax  % = 7.5% × (1 − 11% × Accounting)
Broker Fee % = 3% − 0.3%×Broker Relations − 0.03%×репутация к фракции − 0.02%×репутация к корпорации
```

Оба поля остаются редактируемыми вручную (по умолчанию 0%, как раньше) —
работает и без входа. Применяются к выручке везде на сайте (расчёт одного
предмета и «Поиск по прибыли»): Sell учитывает и то, и другое, Quick Sell —
только Sales Tax (комиссии на покупку/инстант-продажу нет).

## Что не учитывается

- ME указывается одно значение на всю цепочку, а не по каждому чертежу
  отдельно.
- Материалы всегда оцениваются по цене Jita 4-4, даже если производство
  выбрано в другой системе (это цена закупки, а не место постройки).
- «Лучшая система» учитывает только NPC-станции, у которых по статичным
  данным игры есть услуга Manufacturing («Factory») — но не проверяет
  наличие свободных слотов/очереди на них (ESI этого не отдаёт для чужих
  станций). Структуры игроков попадают в список только если добавлены
  вручную или синхронизированы через EVE SSO.
- Расстояние считается только через стар-гейты (обычные прыжки), без
  учёта джамп-драйва/фрейтеров; список игнорируемых систем исключает их
  из графа прыжков полностью (маршрут не может пройти даже транзитом), но
  не умеет отличать «опасно лететь через» от «просто не хочу тут строить».
- «Где продавать» считает ордера по ВСЕЙ выбранной системе (все станции
  сразу), а не по одной конкретной станции — для Jita это станция 4-4, но
  для произвольной системы нет единого «главного» трейд-хаба, который можно
  было бы взять по умолчанию.
- LP-магазины сейчас только Guristas и State Protectorate (захардкожены);
  для чертёжных наград неизвестно число ранов копии — считается стоимость
  и выручка одного рана, не полной копии.

## Обновление данных чертежей (SDE)

Данные о чертежах и материалах берутся из Fuzzwork SDE dump и лежат в
`data/*.json`. Чтобы обновить после патча EVE:

```
rm -r data/raw data/*.json
npm run build-data
```
